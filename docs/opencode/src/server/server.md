# `packages/opencode/src/server/server.ts`

## Overview

This file defines the `Server` namespace, which is responsible for creating and managing a local HTTP server using Hono. This server provides a backend API for the OpenCode TUI and potentially other clients. It handles various functionalities including session management, application state, event streaming (SSE), provider listing, file search, and OpenAPI specification generation.

## Key Components

*   **`app()` (function):**
    *   Initializes a new Hono application instance.
    *   **Error Handling:** Sets up a global error handler that formats `NamedError` instances into JSON responses with a 400 status, otherwise returns a generic unknown error.
    *   **Logging Middleware:** Logs incoming requests (method, path) and outgoing responses (duration).
    *   **API Endpoints:**
        *   `GET /openapi`: Serves the OpenAPI 3.0 specification for the API, generated by `hono-openapi`.
        *   `GET /event`: Establishes a Server-Sent Events (SSE) stream. Clients can connect to this endpoint to receive real-time events published via the `Bus`.
        *   `POST /app_info`: Returns application information (`App.Info`).
        *   `POST /config_get`: Returns the current configuration (`Config.Info`).
        *   `POST /app_initialize`: Marks the application as initialized (`App.initialize()`).
        *   `POST /session_initialize`: Initializes a session, potentially analyzing the app and creating an `AGENTS.md` file. Requires `sessionID`, `providerID`, `modelID`.
        *   `POST /path_get`: Returns key application paths (root, data, cwd, config).
        *   `POST /session_create`: Creates a new session (`Session.create()`) and returns its info.
        *   `POST /session_share`: Shares an existing session (`Session.share()`). Requires `sessionID`.
        *   `POST /session_unshare`: Unshares an existing session (`Session.unshare()`). Requires `sessionID`.
        *   `POST /session_messages`: Retrieves messages for a given session. Requires `sessionID`.
        *   `POST /session_list`: Lists all available sessions.
        *   `POST /session_abort`: Aborts an ongoing operation for a session. Requires `sessionID`.
        *   `POST /session_summarize`: Triggers a summarization process for a session. Requires `sessionID`, `providerID`, `modelID`.
        *   `POST /session_chat`: Sends a chat message to a model within a session. Requires `sessionID`, `providerID`, `modelID`, and `parts` (message content).
        *   `POST /provider_list`: Lists available AI providers and their models, including default model selections.
        *   `POST /file_search`: Searches for files within the project directory using Ripgrep. Requires a `query`.
        *   `POST /installation_info`: Returns installation information (`Installation.info()`).
    *   Uses `describeRoute` from `hono-openapi` to add OpenAPI metadata to routes and `zValidator` for validating request bodies against Zod schemas.
*   **`openapi()` (async function):**
    *   Creates an instance of the Hono app and uses `generateSpecs` from `hono-openapi` to generate the full OpenAPI specification object.
*   **`listen()` (function):**
    *   Starts the Hono HTTP server using `Bun.serve()`.
    *   Configures the server to listen on port `0` (OS assigns a random available port) and hostname `0.0.0.0`.
    *   Sets `idleTimeout` to `0`.
    *   Returns the `Bun.Server` instance.

## Important Variables/Constants

*   **`log` (Log instance):** A logger specific to the "server" service.
*   **`ERRORS` (constant object):** Predefined OpenAPI response schema for 400 Bad Request errors.
*   **Zod Schemas:** Various Zod schemas are used with `zValidator` to define the expected structure of request bodies for different endpoints (e.g., for `/session_chat`, `/session_initialize`).

## Usage Examples

The server is typically started by the main OpenCode CLI process (`packages/opencode/src/index.ts`) when the TUI is launched. The TUI then communicates with this server via HTTP requests to its defined endpoints.

**Starting the server (programmatically):**
```typescript
import { Server } from "./server";

const bunServerInstance = Server.listen();
console.log(`Server listening on ${bunServerInstance.url}`);
// ... later
// bunServerInstance.stop();
```

**Client making a request (example using fetch):**
```typescript
async function createNewSession() {
  const response = await fetch('http://localhost:PORT/session_create', { // Replace PORT with actual
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({}) // Empty body if not required by endpoint
  });
  if (response.ok) {
    const sessionInfo = await response.json();
    console.log('New session created:', sessionInfo);
    return sessionInfo;
  } else {
    console.error('Failed to create session:', await response.json());
  }
}
```

## Dependencies and Interactions

*   **`hono`:** The core web framework used to build the HTTP server and define routes.
*   **`hono-openapi`:** Used for generating OpenAPI documentation from Hono routes and Zod schemas.
*   **`zod`:** Used for schema definition and request validation.
*   **`../util/log` (`Log`):** For logging server activity.

*   **`../provider/provider` (`Provider`):** Used by `/provider_list` to get information about available AI providers and models.

*   **`../global` (`Global`):** Used by `/path_get` for global path information.
*   **`../util/error` (`NamedError`):** Used in the global error handler to provide structured error responses.
*   **`../external/ripgrep` (`Ripgrep`):** Used by `/file_search` to perform file system searches.
*   **`../installation` (`Installation`):** Used by `/installation_info` to get details about the current installation.
*   **`../config/config` (`Config`):** Used by `/config_get` to retrieve configuration data.
*   **`Bun` runtime:** The server is run using `Bun.serve()`.
*   **OpenCode TUI:** The primary client of this server, making requests to its API endpoints to drive the user interface and application logic.
