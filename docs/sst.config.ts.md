# `sst.config.ts`

## Overview

This file is the main configuration file for the Serverless Stack Toolkit (SST) application. It defines global application settings, specifies the cloud platform (Cloudflare in this case), and outlines how to run and deploy the application's infrastructure. The `/// <reference path="./.sst/platform/config.d.ts" />` directive provides TypeScript type checking and autocompletion for SST configurations.

## Key Components

*   **`export default $config({...})`:** The main export is a call to SST's global `$config` function, which takes an object defining the application's configuration.
    *   **`app(input)` (function):** This function defines application-level settings.
        *   `input`: Contains information about the current SST invocation, such as the `stage` (e.g., "production", "dev").
        *   Returns an object with:
            *   `name: "opencode"`: The name of the application.
            *   `removal: input?.stage === "production" ? "retain" : "remove"`: Specifies the removal policy for resources when the app/stage is removed. For the "production" stage, resources are retained; otherwise, they are removed.
            *   `protect: ["production"].includes(input?.stage)`: Determines if the stage's resources are protected from accidental deletion. Only the "production" stage is protected.
            *   `home: "cloudflare"`: Specifies that Cloudflare is the target cloud platform for this SST application.
    *   **`async run()` (function):** This asynchronous function is executed by SST when deploying or running the application. It's responsible for importing and executing the infrastructure definition code.
        *   `const { api } = await import("./infra/app.js")`: Dynamically imports the `api` export (which includes its URL) from the `infra/app.ts` file (compiled to `.js`). This `infra/app.ts` file contains the actual SST constructs that define the Cloudflare resources (Workers, R2 buckets, etc.).
        *   Returns an object `{ api: api.url }`. This makes the API URL available as an output of the SST deployment, which can be useful for other parts of the system or for reference.

## Important Variables/Constants

*   **`$config` (SST global function):** The primary function provided by SST for defining the application configuration.
*   **`input.stage` (within `app` function):** A property provided by SST that indicates the current deployment stage (e.g., "production", "dev", "staging"). This is crucial for stage-specific configurations like removal policies and protection.
*   **`api.url` (from `infra/app.js`):** The URL of the deployed Cloudflare Worker API, which is returned as an output of the `run` function.

## Usage Examples

This file is used by the SST CLI. Developers interact with it indirectly by running SST commands.

**Deploying to a specific stage:**
```bash
npx sst deploy --stage dev
```
When this command is run, SST reads `sst.config.ts`. The `app` function will be called with `input.stage` equal to "dev", and the `run` function will execute, deploying the infrastructure defined in `infra/app.ts`.

**Deploying to production:**
```bash
npx sst deploy --stage production
```
In this case, `input.stage` will be "production", leading to different `removal` and `protect` settings.

**Removing a stage:**
```bash
npx sst remove --stage dev
```
If the stage is "dev", the resources will be removed. If it were "production", they would be retained due to the `removal: "retain"` policy.
